# MoodNomad · 情绪游牧

在线站点：**https://sn0w051201.github.io/-/**

React 19 + TypeScript + Vite + Tailwind CSS 的旅行伴侣网页，暮山紫、沙丘米、落日橘的暖色杂志界面。支持手机和电脑，保留原有旅行总览、行程、AI、账本、清单、足迹、分享海报与偏好数据，并新增目的地发现、图表、照片回忆、年度报告、深色模式。

## 启动

Node.js **22.9+**（生产启动使用 `--env-file-if-exists`），npm：

```bash
npm install
npm run dev
```

Vite 默认监听 5173，并同时提供 `/api/ai` 模型代理，不需要另外启动服务。默认旅行数据保存在当前浏览器，可直接体验离线参考攻略、编辑行程、记账分账、清单打卡、照片与海报。首次载入有可编辑、可删除的种子旅行；已有数据不会自动覆盖。

```bash
npm run typecheck       # 前端、共享领域、后端 TypeScript
npm test                # 领域规则、AA、权限、模型输出、HTTP代理测试
npm run test:e2e        # 桌面和手机尺寸 Chromium 功能回归
npm run build           # 生成 dist/，自动 postbuild 生成 Node 后端
npm run build:server    # 可选：单独重建 server-dist/server.mjs
npm run build:cloud     # 可选：CloudBase 云函数
```

浏览器测试默认使用 `/usr/bin/chromium`；其他机器安装 Chromium 并设置 `CHROMIUM_PATH`。移动测试模拟 iPhone 尺寸，不等于 Safari 或真机验收。

## 配置真实 AI

### 本地开发

1. `npm run dev` 已包含安全代理。
2. 打开“偏好与数据 → AI 模型与安全代理”。
3. 选择 OpenAI、DeepSeek 或通义千问，填写模型名称与自己的 API Key；代理默认 `/api/ai`。
4. 保存配置，到 AI 页点击“生成 AI 攻略”。支持追问，例如“第二天换成室内项目”。

默认 Key 只保留在当前会话的 `sessionStorage`；勾选“记住”后写入 `localStorage`。模型 Key 与代理令牌使用单独的存储键，不进入旅行 JSON 备份、海报或分享。**浏览器存储不加密**，共用设备请勿勾选记住。密钥只发送到配置的代理，再由代理通过 HTTPS 调用白名单模型服务；不要填写不信任的代理地址。请求可能产生模型费用。

也可把 `LLM_API_KEY` 配置为本地开发进程环境变量，不给它添加 `VITE_` 前缀。生产环境使用服务端 Key 时还必须设置访问令牌。开发代理读取进程环境；`.env` 的自动加载由生产启动命令处理，开发时可使用 `node --env-file=.env node_modules/vite/bin/vite.js --host 0.0.0.0`。

默认 OpenAI `gpt-4o-mini`、支持的 GPT-4o/4.1 模型会使用严格 JSON Schema 结构化输出，其他模型/服务保持 JSON 模式兼容。服务端只规范化空坐标、整数数字字符串、单数字小时及无关元数据；不猜测费用、不补造活动。格式失败会带具体字段位置与上次回复请求一次修正，仍不合格则拒绝保存。

“生成离线参考”始终是单独按钮，不调用模型。大理、杭州、成都有详细片区路线，其他城市提供待细化框架；离线内容不会冒充 AI 回复。真实调用失败会显示错误和配置入口，不静默替换成规则数据。

### 在线站点的 AI 后端

Render 可导入仓库的 `render.yaml`：[一键部署入口](https://render.com/deploy?repo=https://github.com/Sn0w051201/-)。已有 Render 服务按 [部署文档](docs/DEPLOYMENT.md#render-一键部署-node-代理) 配置；`npm run build` 会自动构建后端，避免启动时找不到 `server-dist/server.mjs`。

**GitHub Pages 只提供静态网页，不能运行模型代理。** 站点的行程、发现、账本、照片、海报等本地功能可直接使用；真实 AI 需要部署下面的 Node 服务，随后把 `https://你的服务/api/ai` 填入网页设置。仅填写 Key 而没有代理地址不能在 Pages 上调用模型。

在支持 Node 的服务器/容器平台上：

```bash
npm ci
npm run build
# 把 .env.example 复制为 .env，只填写服务端变量与自己的配置
npm run start:server
```

生产服务默认监听 `PORT=8787`，同时提供网页与 API。通过平台 HTTPS 域名或反向代理暴露，代理超时建议 65 秒。独立前后端部署时：

```dotenv
PORT=8787
ALLOWED_ORIGIN=https://sn0w051201.github.io
# 用户每次传自己的模型 Key 时，以下两项可不设置
LLM_API_KEY=在服务器安全填写
PROXY_ACCESS_TOKEN=自设的随机访问令牌
```

`ALLOWED_ORIGIN` 必须是精确来源，不含 `/-/` 路径。省略时使用 `config/web-deployment.json` 中本项目的默认 GitHub Pages 来源，并允许服务同源与 Render 可信环境网址；部署到其他网页来源时请显式覆盖。使用服务器 Key 时，网页填写对应“代理访问令牌”；令牌只给可信用户，公开运营应接正式账号和用户配额。HTTP 接口校验来源、限制请求体和频率、固定上游服务域名，失败不回传上游调试内容。单进程限流按连接 IP，每分钟 12 次；多实例/反代生产需自行配置可信网关与集中限流。

API：`GET /api/health` 返回 `{ok:true}`；`POST /api/ai` 接受 `{provider,model,key?,input}`，可用 `Authorization: Bearer ...`；成功返回经过严格校验的 `GeneratedPlan`。最多重试一次，上游单次超时 45 秒。追问带上之前的结构化结果，模型按要求调整；保存前可预览并编辑。网页按天调用并合并完整攻略，显示进度；中途失败可从草稿继续未完成日期，不重复请求已完成日期。

逐日生成草稿最多保留最近一份、有效期7天，使用单独浏览器存储键，不含 API Key 或代理令牌，不进入旅行备份。刷新后可点击“继续未完成天数”，完成的草稿可不调用模型直接恢复。浏览器空间不足时尝试会话存储，再失败则只保留内存并提示勿关闭页面。支持“完成当前请求后停止”；已发出的当天请求仍可能计费。更换参数/模型会开始新草稿。通用提醒去重保留最多10条，单项推荐、交通、预约和备选完整保留。

### 精细攻略与完整旅行手册

规划表单新增出发地、住宿夜数、季节、抵达返程时间、同行年龄与体力、房型早餐、交通偏好、饮食禁忌、必去/避雷、预算包含范围和其他要求。勾选“生成完整精细攻略”后，先逐日生成路线，再顺序生成4组手册：基础/交通/住宿、美食/景点、安全/工具/行前检查、预算/应急。共约“旅行天数 + 4”次模型请求，质量修正可能增加请求；可取消勾选生成普通路线。单日重规划只生成当天，保留原手册并提醒重新核验。

手册包含11部分与7/3/1天检查，使用可横向滚动的表格、折叠章节，支持下载完整 Markdown 文件。在“我的行程”保存并刷新后仍可查看；下载文件包含旅行偏好，请仅分享给合适的人。核验标识不等于联网查询：模型无实时搜索能力，不保证价格、营业、签证、电话或榜单真实性，必须出发前向官方核对。离线模式提供明确标记的准备模板，不会按所有新增偏好定制或冒充AI。

活动新增 `execution`（必留/可选/可删、体力、人群、营业核验、全员费用区间）；每日新增 `practical`（机动分钟及雨天/排队/闭馆/疲劳方案）。精细模式会拒绝缺少字段、时间重叠、机动时间不足或费用区间矛盾的模型结果。预算七类以人民币整数分存储，校验范围与全员总额；保存预算不产生实际支出。行前检查项合并进原清单，截止日期按出发日前7/3/1天推算。

`POST /api/ai` 增加 `{task:"handbook",group:0..3,plan,input,provider,model,key?}`，返回 `Handbook`。每组结构与列数均校验，最多修正一次，模型请求超时60秒；鉴权、限流、来源限制与普通路线一致。CloudBase 同样支持 `generateHandbook`，计入 `AI_DAILY_LIMIT`，例如默认10次额度未必足够长行程与追问；管理员按预算调整，不在客户端绕过限额。HTTP每分钟12次限制触发时会保留进度，稍后继续。

手册分组也写入7天有效的生成草稿；失败或刷新后只补未完成章节，已完成路线不重复请求。单组进行中关闭网页可能丢失当前请求结果，仍可能计费。新前端需要配套部署最新后端；Render构建 `npm ci && npm run build`、启动 `npm run start:server`，`/api/health` 中 `completeHandbook:true` 表示支持新接口，不需要换同一把API Key。

当前环境未提供真实模型凭据；自动测试用模拟上游验证代理成功/失败与追问传递，没有进行付费真实模型验收。

### 攻略中的饮食与玩乐建议

每日活动直接展示必点菜/必体验、怎么吃/怎么玩、排队预约、人群适配与避雷；保存后仍在原行程内查看。规划表单可选择当地特色、网红店、宝藏小店方向、具体美食和玩乐类型、片区、人均上限、排队时间与预约偏好。支持选填点评门店资料（最多12家）；模型只选择候选ID，后端原样附加店名、地址和来源。地址可复制并打开地图搜索导航；缺失地址、剪贴板失败都有降级。不读取点评链接、不抓取点评数据，不声称接入实时评分/榜单。

字段、真实性规则及后端提示词见 [饮食玩乐建议说明](docs/LOCAL_RECOMMENDATIONS.md)。新前端需要同步更新后端，健康检查应含 `localAdvice:true`，无需更换原模型Key。旧行程仍可查看；新增建议需重新生成。离线参考会标明为规则建议，不自动选用用户门店或伪装为AI定制。

### 可选 CloudBase 模式

原有云端能力保留，详见 [部署步骤](docs/DEPLOYMENT.md)、[数据库集合](docs/DATABASE.md)。设置 `VITE_DATA_MODE=cloud` 和本地 `VITE_CLOUDBASE_ENV_ID` 后构建，并部署 `api` 云函数、身份与权限规则；模型 Key 只放云函数环境变量。云模式 AI 使用云函数的配置，不使用浏览器自定义 HTTP 代理配置。当前云身份是匿名登录，非正式微信登录。

新增照片墙目前仅支持本地模式；云端照片上传/读取尚未接入。发现收藏和主题的云同步尚未实现。CloudBase 部署与真实多账号协作需独立验收，不能以静态网站测试替代。

## 数据结构与迁移

存储键 `moodnomad-web-v1`，`schemaVersion:1`；新增字段均可选，兼容原备份。

- `AppState`：`userId/profile/activeTripId/trips`，新增 `favorites/customDestinations/destinationEdits/hiddenDestinations/feed/preferences.theme`。
- `Trip`：目的地、开始日期、预算、成员、`days[].items`、`expenses`、`checklist`；新增 `visited`、`photos[]`、`travelProfile`、`handbook`、`guideSummary`、`guideAssumptions`。
- `Activity`：名称、时间、类型、耗时、`costMinor`、位置、打卡、`slot`、推荐详情、可选的 `execution`；`days[].practical` 保存机动时间与预案。费用预估从这些字段推导，无独立虚假支出记录。
- `Expense`：付款人、参与成员、整数金额、分类、分摊类型与份额、日期、备注、凭证、幂等键；可选 `estimateId` 关联原活动。
- `TravelPhoto`：`id/src/caption/takenAt/createdBy`，本地 JPEG 数据；按拍摄日期倒序生成回忆时间轴。
- `Destination`：城市/地区/国家、坐标、建议月份/天数/人均预算、主题、亮点、美食、路线、贴士、照片与来源。内置目录与用户修改/新增合并展示。

本地最多 100 场旅行，每场最多 20 人、14 天、每天 8 项、100 笔支出、200 项清单、30 张照片；整个本地备份校验上限 4.5MB。照片最长边 1000px、JPEG 压缩后单张需小于 650KB。存储超限时拒绝保存，不宣称修改已持久化。浏览器自身配额可能更低，请定期导出。导入会校验、要求替换确认；备份含照片/凭证/个人资料，请勿公开。

AA 金额统一使用整数“分”。平均分按稳定成员 ID 分配余数；比例使用 BigInt 最大余数法；指定金额合计必须等于总额。结算按净余额与稳定 ID 生成确定性转账建议，不承诺全局最少笔数，不发生真实支付。测试覆盖平均分、指定参与人、余数、比例/固定金额、多债权债务及金额守恒。

## 内容来源与边界

- 56 个目的地的路线、美食、季节、预算是静态编辑参考，不是实时行情。可自行增删改查；详情页提示核验预约、签证/签注、交通和出行时间。
- 大众点评、必吃榜、米其林是候选核验渠道，当前没有实时授权榜单 API；不抓取登录页面，不伪造评分/排名/上榜年份，不声称读取用户粘贴的链接。
- 发现页使用随网站发布的**真实摄影风景参考**，不是各城市实拍图库；可在目的地编辑中替换为自己的已授权照片。主页旧封面仍为生成的灵感插图。来源与许可证见 [第三方说明](THIRD_PARTY_NOTICES.md)。
- 城市地图使用 Natural Earth 公共领域数据，仅为旅行记忆示意。去过状态来自手动标记或行程打卡；未知坐标不会虚构。里程是已知目的地列表相邻点间的直线距离估算，不是导航/实际交通里程。各场旅行天数简单相加，不合并重叠日期。
- 天气请求 Open-Meteo 当前模型数据，显示时间和来源；失败可重试，不拿模拟天气充当实时预报。
- 本地快照链接包含所选摘要，持有链接者可读，生成后不可撤销；照片、密钥、凭证和私人清单不会自动进入分享。
